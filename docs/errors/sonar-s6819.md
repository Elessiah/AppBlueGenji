## Analyse

**SonarQube · code smell · major · typescript:S6819** (93 occurrences restantes sur 96) — Prefer tag over ARIA role — TRIÉ (feature/sonar-a11y) : 3 corrigées (`<div role="region" aria-label…>` → `<section aria-label…>` dans BoardPanel, AccessibilityMenu, client-power-badge : même rendu, même rôle). Le reste n'a pas d'équivalent natif sans changement de style ou de comportement — familles : (1) `role="dialog"` sur `<div>` (~27) — convention des modales (portail + useDialogBehavior + useBackdropDismiss) ; `<dialog>` natif changerait couche supérieure, Échap et `::backdrop` ; (2) `role="presentation"` sur le voile des modales (~30) — aucun équivalent, la règle propose `<img>` ; (3) `role="status"` sur `<p>`/`<div>`/`<span>` (~20) — `<output>` est en ligne et associé aux formulaires : bascule possible écran par écran avec une classe `display: block` ; (4) `role="group"` (~16) — `<fieldset>` apporte bordure, marge et `<legend>` ; à migrer avec un reset de style ; (5) `role="img"` sur `<svg>`/pastilles (~9) — schémas SVG nommés, `<img>` impossible ; (6) `role="list"`/`listitem` sur pastilles en flex (StatsPanel), `progressbar` (TournamentProgress), `listbox`/`option` des combobox (PlayerPseudoCombobox, TargetPicker), `region` de ScrollArea (conditionnel) et de recruitment-highlight (écouteurs de pause) — composants sur mesure. Pistes restantes : familles (3) et (4) avec un reset CSS — décision utilisateur. — (rencontré sur : feature/sonarqube-docker-deploy-06e2c9)
